# Izan Bling ERP - Architecture

## Core Tech Stack
*   **Framework:** Next.js (App Router)
*   **Database Engine & API:** Supabase (Provides PostgreSQL hosting and instant client-side APIs to eliminate manual API writing).
*   **Database Schema Manager:** Prisma (Used strictly to define and migrate database tables).
*   **Styling:** Tailwind CSS integrated with Dynamic CSS Variables.
*   **Visual Engine:** GrapesJS (Powers the Canva-style drag-and-drop storefront builder).

## Directory & Module Structure
The project strictly follows this Next.js folder organization to separate the customer storefront from the secure ERP admin panel:
*   ** `app/(erp)
    *  *Purpose:*The erp modules related to accounting.
    *Example:* `/accounts (Chart of accounts)  

*   **`app/(storefront)/shop/`** 
    *   *Purpose:* The main, customer-facing e-commerce store.
    *   *Example:* `/shop` (Home), `/shop/product/[id]` (Product Details).
*   **`app/(storefront)/shop/p/[slug]/`** 
    *   *Purpose:* Dynamic catch-all route for customer-facing custom landing pages (like a "Summer Sale" or "Link-in-bio" page) generated by the Visual Builder.
*   **`app/(storefront)/shop/admin/`** 
    *   *Purpose:* The secure ERP dashboard. Only authorized users can access this.
    *   *Modules:* `/admin/design` (Visual Editor), `/admin/funnels` (Funnels Manager), `/admin/products` (Inventory).
*   **`app/api/`** 
    *   *Purpose:* Secure backend route handlers (used for webhooks, payments, or complex operations that cannot be handled directly by the Supabase client).
*   **`app/components/`** 
    *   *Purpose:* Reusable global UI pieces (e.g., `<AddToCartButton />`, `<Sidebar />`).
*   **`app/lib/`** 
    *   *Purpose:* Core configurations, helper functions, and database clients (e.g., `prisma.ts`, `supabase.ts`).

## System Paradigms (How the Software Behaves)
1.  **Global Dynamic Theming:** The software's design is not hardcoded in the files. Global colors, fonts, and layouts are stored in the database settings. On load, these settings generate CSS variables (e.g., `var(--theme-primary)`) so that updating the settings instantly updates the entire ERP and storefront.
2.  **Direct Database Access (BaaS):** To speed up development, the ERP admin panels should leverage the Supabase Client SDK for direct data fetching, avoiding the need to write custom Next.js API routes for every single CRUD (Create, Read, Update, Delete) operation.
3.  **JSON-Driven Storefront:** Custom pages (Home, About, Sales) are built visually. The layout is saved as raw HTML/CSS blobs in the database and rendered dynamically via the `p/[slug]` route.
4.  **Next.js 15+ Compliance:** All dynamic route parameters (e.g., `params.id`, `params.slug`) must be explicitly unwrapped using `await` before access.
